# proxy-waf Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** A persistent MITM proxy that terminates TLS, evaluates OWASP CRS in detection-only mode, records every request, and serves it through a filterable web UI.

**Architecture:** A Go reverse proxy captures transactions and writes them to a disk spool, which a shipper batches into ClickHouse. A separate Go API reads ClickHouse for queries and Postgres for configuration, and serves a React SPA.

**Tech Stack:** Go 1.26, Coraza v3 + OWASP CRS 4, ClickHouse, Postgres 16, React 19 + TypeScript + Vite + Tailwind, Docker Compose.

**Spec:** `docs/superpowers/specs/2026-09-08-proxy-waf-design.md`

**Status:** Complete. All 22 tasks implemented and verified; see the README for
what shipped and `make test-all` for the suite.

## Global Constraints

- Go module path: `github.com/amzteodor/proxy-waf`. Go 1.26.
- Request path never performs a database call. Events reach ClickHouse only through the spool.
- Response bodies are never buffered or inspected. Coraza phases 1–3 only.
- Redaction runs in the proxy before an event is written to disk.
- Pagination is keyset on `(ts, id)`. No `OFFSET` in any query.
- Filter values reach ClickHouse only as bound parameters. Column and operator names come from an allowlist.
- Retention default 90 days, per-app override.
- Documentation is GitHub-flavored markdown, succinct. Code comments only where intent is not evident from the code.
